# 认知分身插件规范与约束

当本插件启用时，以下规则常驻生效：

1. **零交接摘要原则**：
   * 严禁为主会话派发的分身子代理（`TypeName: "twin"`）手写长篇背景 Briefing 或手动拼接历史日志。
   * 充分利用前缀缓存（Prompt Caching），只传 1~2 句核心目标指令。

2. **工作区防写竞争原则**：
   * 凡是需要分身执行代码修复、文件写入的任务，`Workspace` 参数必须设为 `"share"` 或 `"branch"`，利用隔离分支或共享工作树机制，防止主子代理并发修改导致脏工作区。
   * 纯分析、排查、复盘类任务可使用 `"inherit"`。

3. **异步非阻塞准则**：
   * 派发分身后，主会话默认保持异步推进，不得无故主动休眠等待分身，除非用户明确要求“等待复盘结果再继续”。
   * 分身与主线程的沟通严格遵循 `send_message` 结构化信件格式，无重大变更不发无意义闲聊。

4. **主控独占调度与并发池节流准则（参考 Claude Code 架构）**：
   * **全局独占权**：全局拓扑图、最大深度/章节上限（`max_depth`）以及子代理激活权**完全由主会话独占**。严禁分身子代理绕过主会话私自递归无限裂变。
   * **并发池节流（批次 ≤ 6 个）**：面对指数级分支（如 3 变 9、9 变 27）或大规模多智能体协作时，主会话必须维护待激活任务队列（Task Queue），采用滑动窗口分组激活，**单批次并发严格控制在 ≤ 6 个智能体**，防止 API 限频、资源耗尽与智能体雪崩。

5. **分身局部单线与终局自决准则**：
   * **单线沉浸**：每个分身子代理只专注于自己的线性因果与连续体验，无需承担全局多分支调和压力。
   * **本步终结自决**：分身拥有对当前分支的本步自决权，自主评估当前步是“达成终局（Good End / Bad End / Normal End）”还是“产生分歧选项”。若产生新分支，仅向主会话提交候选选项，由主会话决定是否入队并在后续批次中激活。
