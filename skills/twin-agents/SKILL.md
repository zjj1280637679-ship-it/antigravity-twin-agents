# 同文孪生分身技能 (Twin Agents Skill)

使用此技能可以在 Antigravity 中派发**解耦局部惯性、保持单线自决的异步分身子代理**。

> **⚠️ Antigravity 上下文传递机制说明**：  
> Antigravity 的 `invoke_subagent` 启动时为独立会话，**不自动继承父会话的消息流**。本技能通过 **“文件系统共享现状 (C)”** 与 **“显式前缀注入目标与因果链 (G / Ancestral Chain)”** 两种严谨机制实现上下文无损传递，并在大文本分支时利用 Gemini 的 **物理前缀缓存（Prefix Caching，门槛 >= 4096 tokens）** 实现高吞吐。

---

## 一、 分身的两大运行模式与调用规范

### 模式一：认知复盘分身 (Cognitive Review Twin)
用于**复杂代码交付前夕、疑难 Bug 修复后、核心假设验证**。分身摆脱主对话的局部策略压力，以 $(G, C, S', M')$ 重新审视现状。

* **上下文承载方式**：
  * **事实与证据 $C$**：分身直接通过 `view_file`、`run_command (git diff)` 查阅工作区实际文件（`Workspace` 推荐设为 `"share"` 或 `"branch"`，杜绝主子写入竞争）。
  * **根目标 $G$**：主会话在 Prompt 中**显式注入用户原始诉求与核心边界**（不再假设分身具有超感官读取历史的能力）。
* **标准调用示例**：
```json
invoke_subagent({
  "Subagents": [{
    "TypeName": "twin",
    "Role": "代码认知复盘分身",
    "Workspace": "share",
    "Prompt": "【根目标 G】用户要求实现带并发池(<=6)与祖先亲和度排序的故事树调度器。\n【现状 C】核心逻辑已写入 scripts/story_tree_scheduler.py。\n【重推解法 S'】请从第一性原理核查当前实现是否存在队列死锁、深度溢出或未捕获异常。低风险边界可直接补全测试修复，重大架构隐患使用 send_message 写信汇报。"
  }]
})
```

---

### 模式二：叙事推演分身 (Narrative Story Twin)
用于**文字冒险游戏、分支互动小说、跑团剧情树生成**。分身沉浸于单线因果，避免多线调和带来的疲软与剧透。

* **上下文承载方式**：主会话将当前线自起点累积的剧情链作为**显式前缀**注入 Prompt 前半部。
* **标准调用示例**：
```json
invoke_subagent({
  "Subagents": [
    {
      "TypeName": "twin",
      "Role": "支线A推演分身",
      "Workspace": "inherit",
      "Prompt": "【前序因果链（公共前缀）】\n<此处填入从根节点到父节点累积的剧情文本>\n\n【本支线专属抉择】\n你选择了【拔剑迎战】。请在此因果基础上推演本步（300~400字），自主评估是否达成结局；若未结局请给出下一步分歧选项。"
    },
    {
      "TypeName": "twin",
      "Role": "支线B推演分身",
      "Workspace": "inherit",
      "Prompt": "【前序因果链（公共前缀）】\n<此处填入从根节点到父节点累积的剧情文本>\n\n【本支线专属抉择】\n你选择了【潜行绕后】。请在此因果基础上推演本步（300~400字），自主评估是否达成结局；若未结局请给出下一步分歧选项。"
    }
  ]
})
```

## 二、 祖先亲和度分组与 Prefix Caching 物理命中机制

根据 Google 官方文档，Gemini 系列模型的隐式前缀缓存（Implicit Prefix Caching）要求**输入前缀达到最低阈值（Gemini 3.8 Flash 为 4,096 Tokens）**。

为了最大化命中缓存，调度器采用**祖先亲和度排序算法（Ancestor-Grouped Batching）**：
1. **亲和度聚合**：同一批激活的 6 个分身，优先安排给**共享相同父节点/祖先链**的任务（如 `A1, A2, A3` 优先同批，而不是随机散列 `A1, B1, C1`）。
2. **长历史跨越门槛**：随着故事树深入到第 3 层以上，前序剧情文本逐渐累积超过 4,096 Tokens，同批次内的分身将稳定触发物理 Prefix Caching，使深层分支推演的边际 Token 成本大幅下降。

## 三、 主会话调度池管理准则 (Concurrency Pool <= 6)

1. **独占调度权**：严禁分身私自递归派发孙分身；所有激活权、最大层数（`max_depth`）归主会话统控。
2. **滑动窗口节流**：无论待处理队列有多少任务，同时运行的分身数不得超过 6。
3. **结构化回传解析**：分身完成单步推演后，通过 `send_message` 发送 `branch_step` 信件，主控解析 `is_ending` 与 `next_branches` 自动入队并推进。
