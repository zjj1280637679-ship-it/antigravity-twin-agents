# 同文孪生分身技能 (Twin Agents Skill)

使用此技能可以在 1 秒内为主会话派发一个**共享完整认知现场的异步分身**。

---

## 一、何时派发分身？

在以下场景，不要让主会话陷入琐碎的扫尾或纠结的复盘中，直接派发分身：

1. **复杂功能交付前夕**：主线代码写完了，让分身去查遗漏的边界、漏写的测试、文档漂移。
2. **疑难 Bug 排查后**：问题表面修复了，让分身去独立核查“底层前提假设真的成立吗？有没有引入回退？”
3. **主任务已切换，但有未尽事宜**：主会话急需进入下一个用户需求，让分身在后台把刚刚积累的经验沉淀为文档或提交记录。
4. **验证指标怀疑**：测试全绿了，但怀疑测试是否真的覆盖了用户的原始根本诉求。

---

## 二、极简调用规范（复杂度 ≤ 普通子代理）

因为分身**原生继承全部认知上下文**（命中 Prompt Cache，极速且成本低廉），主代理**严禁花费精力手写冗长的背景摘要（Briefing）**。

只需发起一个最简单的 `invoke_subagent` 调用：

```json
invoke_subagent({
  "Subagents": [{
    "TypeName": "twin",
    "Role": "认知分身",
    "Workspace": "share",
    "Prompt": "复盘当前代码修改，重点核查边界条件与未处理异常，低风险问题直接修复，关键发现回信汇报。"
  }]
})
```

### 关键参数说明：
* **`TypeName`**：固定为 `"twin"`。
* **`Workspace`**：推荐使用 `"share"`（基于类似 git worktree 机制共享仓库但独立工作）或 `"inherit"`（只读/检查时）。
* **`Prompt`**：**只需一两句话说明核心目标与侧重点**。不要重复阐述项目背景，分身全都知道。

---

## 三、派发后的主代理准则

1. **不要等待，保持前行**：派发完成后，主代理直接继续响应用户或推进下一项工作。分身完全在后台异步运转。
2. **响应式唤醒**：当分身通过 `send_message` 发回关键发现时，系统会自动唤醒你。届时只需阅读分身的 `finding` 和 `evidence`，裁决是否采纳其建议即可。

---

## 四、多智能体分批调度与故事树编排（参考 Claude Code 架构）

当面对**文字冒险故事树（1分3、3分9）**或几十个并发任务时，严禁一次性激活几十个智能体，必须遵循**“主控池化节流（Concurrency Pool ≤ 6）”**模式：

### 1. 核心调度流程
1. **树深度控制（Max Depth）**：由主会话在全局维护 `current_depth` 与 `max_depth`。
   * 若 `current_depth < max_depth`：提示词告知分身“推演本步剧情，评估是否达成结局；若未结局请给出 2~3 个新选项”。
   * 若 `current_depth >= max_depth`：提示词强制约束“已达到最大章节深度，本步必须根据前因后果编写收束结局（Good End / Bad End），禁止产生新选项”。
2. **待执行队列（Task Queue）**：所有子分身汇报上来的候选分支，由主会话收集并排入队列。
3. **分批激活（Batch Throttling）**：主会话每次从队列中**最多弹出 6 个分支节点**并发调用 `invoke_subagent`。上一批完成后，再弹出下一批 6 个。

### 2. 调度示例调用
```json
invoke_subagent({
  "Subagents": [
    {
      "TypeName": "twin",
      "Role": "支线A推演分身",
      "Workspace": "inherit",
      "Prompt": "沿【选择拔剑迎战】路线推演剧情。自决本步是否达成结局；若未达成请提供下一步分歧选项。"
    },
    {
      "TypeName": "twin",
      "Role": "支线B推演分身",
      "Workspace": "inherit",
      "Prompt": "沿【选择潜行绕后】路线推演剧情。自决本步是否达成结局；若未达成请提供下一步分歧选项。"
    }
  ]
})
```
